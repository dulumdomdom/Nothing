# Система управления классификаторами и справочниками

Полный дизайн: роли, подсистемы, use case, сценарии, жизненные циклы, модель данных, права, статусы и краевые случаи.

---

## 1. Роли (акторы)

| Роль | Зачем существует | Что делает |
|---|---|---|
| **Пользователь** | конечный потребитель данных | ищет коды, просматривает, подаёт заявки на пополнение/изменение |
| **Модератор справочников** | держит в порядке плоские списки (регионы, ед. измерения, валюты, организации) | проверяет и применяет заявки по справочникам, чистит дубликаты |
| **Модератор классификаторов** | держит в порядке иерархии (ОКВЭД, ОКПД, МКБ, ТН ВЭД и т.п.) | проверяет и применяет заявки по классификаторам, правит структуру, версионирует |
| **Администратор** | не трогает контент, управляет системой | пользователи, роли, права, настройки, импорт, журнал аудита |

Ключевое разграничение: **модераторы работают с содержанием, администратор — с доступом и конфигурацией**. Это и есть «сложность» системы.

---

## 2. Функциональные подсистемы

1. **Каталог и навигация** — просмотр дерева классификатора, списков справочников, drill-down по узлам.
2. **Поиск и подбор кода** — поиск по коду, наименованию, синонимам, полнотекстовый, подбор «снизу вверх» по классификатору.
3. **Заявки на пополнение/изменение** — единый механизм предложений от пользователей.
4. **Модерация справочников** — очередь заявок, пополнение, объединение дублей.
5. **Модерация классификаторов** — очередь заявок, правка структуры, версионирование.
6. **Версионирование и публикация** — актуальная/черновая/архивная версии, даты действия.
7. **Импорт/экспорт и интеграция** — пакетная загрузка, обмен с внешними источниками, API.
8. **Администрирование и RBAC** — пользователи, роли, разрешения.
9. **Аудит и журналирование** — кто/что/когда/почему изменил.
10. **Уведомления** — статусы заявок, комментарии модераторов.

## 4. Ключевые сценарии

### SC-01. Заявка на пополнение классификатора

**Предусловие:** пользователь авторизован, нашёл узел.

1. Открывает узел классификатора → «Предложить пополнение».
2. Выбирает тип операции: *добавить дочерний узел*.
3. Заполняет: код, наименование, синонимы, обоснование, прикладывает документ-источник.
4. Система проверяет: формат кода, уникальность, дубликат по наименованию.
5. Отправка → статус `Отправлена`, автоназначение на модератора классификаторов.

**Альтернативы:**
- 3а. Код уже занят → система показывает существующую запись и предлагает «это то же самое?».
- 3б. Похожее наименование (>0.9 схожести) → предупреждение о вероятном дубликате.
- 4а. Поля пустые/невалидные → подсветка, блокировка отправки.

**Постусловие:** заявка в очереди модератора, автор получает уведомление.

### SC-02. Модерация заявки (полный цикл)

1. Модератор открывает очередь, фильтр по типу объекта.
2. Открывает заявку, видит: предлагаемые данные, целевой узел, историю, похожие записи.
3. Принимает решение:
   - **Одобрить** → система применяет изменение, создаёт/обновляет узел, пишет в журнал.
   - **Отклонить** → обязательный комментарий причины.
   - **Вернуть на доработку** → комментарий, что поправить.
4. Автор получает уведомление о любом исходе.

**Альтернативы:**
- 3а. Обнаружен дубль → «объединить»: заявку отклонить с пометкой, существующую запись обогатить синонимом из заявки.
- 3б. Изменение затрагивает актуальный классификатор → предложить отложить в черновую версию (см. SC-03).

### SC-03. Версионирование классификатора

**Правило:** актуальная версия неизменяема. Любое изменение идёт в черновик.

1. Модератор инициирует «Новая версия» от актуальной.
2. Система создаёт `Черновая` версию (копия структуры).
3. Модератор вносит правки (узлы, коды, переносы).
4. **Публикация:** черновая → `Актуальная`, старая → `Архивная`, фиксируются даты действия.
5. Пользователи сразу видят новую актуальную версию; в отчётах можно ссылаться на архивную (историчность).

**Альтернативы:**
- 3а. Правки зависли → версию можно откатить, архивные не удаляются никогда.
- 3б. Несогласованность кодов → проверка целостности перед публикацией (нет висячих ссылок).

### SC-04. Объединение дубликатов (справочник)

1. Модератор находит две записи-дубля (или система предлагает автоматически по схожести).
2. Выбирает «каноническую» запись.
3. Система показывает, где используется «лишняя» (ссылки из классификаторов/заявок).
4. Подтверждение → все ссылки переезжают на канон, «лишняя» деактивируется (не удаляется), в журнале — запись.

### SC-05. Импорт из внешнего источника

1. Модератор загружает файл (XML/CSV) или подключает источник.
2. Система строит «план изменений»: добавить / изменить / деактивировать / конфликты.
3. Модератор просматривает diff и подтверждает по группам.
4. Применение в черновую версию → публикация.

### SC-06. Назначение прав (админ)

1. Создаёт/редактирует пользователя.
2. Назначает роль(и) из списка.
3. Система применяет RBAC: права = объединение разрешений ролей.
4. Изменение вступает в силу сразу, фиксируется в аудите.

## 5. Жизненный цикл заявки

```
Черновик ──отправить──▶ Отправлена ──автоназначение──▶ На рассмотрении
   ▲                                                    │
   │        ┌───────────доработка──────────────┐        │
   └─правки─┤                                   │        │
            │        ◀──Возвращена на доработку─┘        │
            │                                            │
            │           ┌────────────Одобрена────────────┤
            │           ▼                                │
            │      Применена (изменение внесено)         │
            │                                            │
            └───────────────Отклонена (конец)            │
Отменена автором (из Черновика/Отправленной)
```

Переходы:
- Черновик → Отправлена (отправить)
- Черновик → Отменена (отменить)
- Отправлена → На рассмотрении (автоназначение)
- Отправлена → Отменена (отозвать)
- На рассмотрении → Возвращена (вернуть)
- Возвращена → На рассмотрении (доработать и подать)
- На рассмотрении → Отклонена (отклонить)
- На рассмотрении → Одобрена (одобрить)
- Одобрена → Применена (применить изменение)

## 6. Модель данных

| Сущность | Назначение | Связи |
|---|---|---|
| `User` | пользователь | → `Role` (N:N), → `Request` (автор/модератор) |
| `Role` / `Permission` | роли и разрешения | N:N |
| `Classifier` | классификатор | → `ClassifierVersion` (1:N) |
| `ClassifierVersion` | версия (draft/active/archived) | → `ClassifierNode` (1:N) |
| `ClassifierNode` | узел иерархии | self-ref (parent), → `DirectoryEntry` (атрибуты) |
| `Directory` | справочник | → `DirectoryEntry` (1:N) |
| `DirectoryEntry` | запись справочника | — |
| `Request` | заявка | → `User` (автор), → `User` (модератор), полиморфный target |
| `RequestStatusHistory` | история статусов | → `Request` |
| `ImportBatch` | пакет импорта | → `User`, target |
| `AuditLog` | журнал изменений | → `User`, любой объект |
| `Notification` | уведомление | → `User` |

Атрибуты ключевых сущностей:

- `User`: id, login, email, fio, active
- `Role`: id, code, name
- `Permission`: id, code, name
- `Classifier`: id, code, name, type, current_version_id, status
- `ClassifierVersion`: id, classifier_id, version_number, status, valid_from, valid_to
- `ClassifierNode`: id, version_id, code, name, parent_id, level, order
- `Directory`: id, code, name, type
- `DirectoryEntry`: id, directory_id, code, name, synonyms, active
- `Request`: id, number, type, target_type, target_id, status, author_id, assignee_id
- `RequestStatusHistory`: id, request_id, from_status, to_status, comment, at
- `ImportBatch`: id, source, status, created_by, at
- `AuditLog`: id, user_id, action, entity_type, entity_id, at
- `Notification`: id, user_id, text, read

## 8. Словари-статусы

- **Заявка:** Черновик, Отправлена, На рассмотрении, Возвращена, Отклонена, Одобрена, Применена, Отменена.
- **Версия классификатора:** Черновая, Актуальная, Архивная.
- **Запись справочника / узел:** Активна, Деактивирована (никогда не удаляется физически).
- **Тип операции в заявке:** Добавление, Изменение, Исключение, Объединение дублей, Перенос узла.

## 9. Краевые случаи и правила

- **Дубль по коду** — блокировка, предложение существующей записи.
- **Дубль по наименованию** — предупреждение + подсказка модератору.
- **Изменение актуальной версии** — запрещено, только через черновик.
- **Конкурентное редактирование** — оптимистичная блокировка (версия объекта).
- **Деактивация, а не удаление** — историчность для отчётности и ссылок.
- **Публикация с висячими ссылками** — проверка целостности перед публикацией.
- **Всё в аудите** — кто, что, когда, откуда (заявка/импорт/прямое), почему (комментарий).

---

## 10. Глоссарий

- **Классификатор** — иерархическая структура классов с кодами (например, ОКВЭД, ОКПД, МКБ, ТН ВЭД).
- **Справочник** — плоский (или простой) список допустимых значений (регионы, единицы измерения, валюты).
- **Узел** — элемент дерева классификатора (код + наименование + родитель).
- **Пополнение** — добавление новой записи/узла в классификатор или справочник.
- **Заявка** — предложение пользователя на изменение, проходящее модерацию.
- **Версия** — неизменяемый срез классификатора на момент времени (черновая/актуальная/архивная).
- **Деактивация** — перевод записи в неактивное состояние без физического удаления.
